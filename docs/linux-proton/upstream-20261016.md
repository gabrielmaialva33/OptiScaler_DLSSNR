# OptiScaler upstream integration, 2026-10-16

Merge `optiscaler/master` at `0e42d595` (19 commits after the prior upstream tip `5108b6df`)
onto Retoque `03eea0d0`, including its automated D3D12 input fixture. Work remains on
`merge/optiscaler-20261016` until integration is accepted; no game deployment is part of this merge.

## Upstream behavior

- Vulkan upscaler inputs can feed frame generation; a Vulkan DLSS-G output and HUD capture/unblend are added.
- DLSS-G constants/options move into `DLSSG_Common`, shared by DX12 and Vulkan.
- Streamline initialization separates common setup from the D3D12/Vulkan device registration.
- FG status/FPS, Quirks/ASI presentation and the multiplier slider follow upstream.
- Vulkan headers use the C API. The solution and OptiScaler project drop Win32 configurations; x64
  and the NR forwarder remain. No submodule version changes or recursive update are required.

## Resolution decisions

- The D3D12 overlay retains Retoque's completion tickets, allocator/cleanup waits and retained queue.
  These already cover upstream `f062eee2`; do not layer its second fence/event implementation on top.
- The Vulkan hooks retain the NR present host, supported extension augmentation, DXGI caller identity,
  scoped hook suppression and per-queue recursive locks. Device preparation follows upstream's FG
  preparation, then spoofing once, then the supported NR extension additions.
- The common DLSS-G implementation retains exact-frame game camera ownership, menu interlock,
  MFG count reinitialization, option caching/generation invalidation and Reflex Boost. Camera lookup
  keeps the 64-bit logical ID; conversion to the SDK's 32-bit token ID happens afterward.
- Binding active Streamline features retains per-group bundled fallback, clearing every member of
  an incomplete group first. D3D12's device wrapper preserves its nonfatal binding policy. Vulkan
  initialization requires all mandatory functions after fallback, so incomplete plugins cannot
  advertise a ready device. Missing Reflex options fails without a null call.
- An options cache advances only after a successful SDK write. A transient refusal must be retried
  on the next frame; migrating the cache to Vulkan must not suppress upstream's retries.
- The second-device quirk still binds immediately for a D3D11 bridge, which has only one D3D12 device.
- Upstream's FG overlay-bypass callback uses the bundle's private present trampoline, which bypasses
  the NR host's later export detour. Forward that callback explicitly through the host when installed,
  retaining raw passthrough when it is off. A thread-local present scope rejects duplicate observation
  of the same queue/swapchains/images, but still observes nested FFX real presents beneath the game's
  distinct proxy swapchain. The callback must call the raw present exactly once and consume no extra
  ICD detour slot. The existing FSR-FG transport GPU case is the regression oracle for this route.
- Camera tests now extract the actual common implementation. Resource-tag fixtures carry Vulkan's
  new image-view member. The optional pt-BR pack includes the new Quirks/ASI titles.

## Verification boundaries

Host sanitizers cover binding groups, initialization guards, option retries, camera identity and
overlay lifetimes. The standalone MSVC/DirectXMath/D3D12 fixture checks camera reconstruction order
and real texture crop/readback with required failing controls. The production DLL's Vulkan present
host harness checks actual hooks/transport under synchronization validation, including its FSR-FG
transport case. Release compilation and clang-format 22 are separate checks.

These checks do not establish generated-frame image quality, real DLSS-G Vulkan inference/pacing,
or native Windows D3D12 validation. The FSR-FG transport case does not submit interpolation inputs
and therefore does not claim generated frames. No performance improvement is inferred from a pass.

The paired FSR-FG validation keeps its existing strict comparison of error reports and live child
objects against the untouched arm. One run concurrent with another GPU fixture reported 95 versus
76 objects; its cause was not established. Three subsequent serial pairs, with full validation object
inventories, each reported 76 in both arms and no extra host error. Retain serial GPU execution and
the strict check; the provider/overlay's existing reports are not a clean-device validation result.
